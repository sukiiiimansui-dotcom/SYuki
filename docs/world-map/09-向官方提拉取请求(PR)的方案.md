## 一、先回答最关键的问题：**哪个分支 比 哪个分支**

```
head（我们这边要提的分支）              base（要求官方拉进哪个分支）
─────────────────────────────         ──────────────────────────────
sukiiiimansui-dotcom/LingChat          SlimeBoyOwO/LingChat
  └─ feat/world-map                      └─ dev          ← 注意：不是 main
       （fork 里，从 fork 的 dev 切出）
```

**base = `dev`，不是 `main`。** 证据（实测）：

| 证据 | 数据 |
|---|---|
| 最近合并的 PR 目标分支 | `dev` × 23，`main` × 0 |
| 当前开放的 PR 目标分支 | `dev` × 23，`main` × 3 —— 那 3 个全是维护者自己的热修（如 `SlimeBoyOwO:fix/persistent-memory-phase1`） |
| 两个分支的活跃度 | `main` 停在 **2026-09-01**（`ef8f7914`，= 0.5.1 发布点）；`dev` 已经到 **2026-09-11**（`957f3ad8`），领先 main 24+ 提交 |

也就是说：**`main` 是发布分支，`dev` 才是开发分支**，社区 PR 一律进 dev。

**head 必须是 fork 的分支**，原因：
- GitHub 只接受「同仓库分支」或「**fork** 的分支」作为 PR head；
- 我们的 `SYuki` 仓库与官方是**两段互不相连的历史**（当初是独立导入的快照，不是 fork），
  从 SYuki 的分支提 PR，GitHub 会按"无共同祖先"算出整个仓库重写，根本没法 review。

**好消息：fork 是服务端复制，秒级完成，不需要我们上传官方几万个历史对象。**

### 3.2 commit 组织（建议 3 个，语义清晰）

1. `feat(world-map): 地图数据层与图层组件`
   —— `worldMap.ts` + `WorldMapLayer.vue` + composables + `App.vue` 接线
2. `feat(world-map): 地图页面与入口`
   —— `WorldMap.vue` + router + 主菜单入口
3. `feat(world-map): Rust 侧世界地图模块与命令`
   —— `src-tauri/src/world_map/*` + `lib.rs` 命令注册 + `Cargo.toml`

> 拆开的好处：维护者可以逐个看、逐个小步反馈；万一某个模块有异议，砍掉它不影响前两个。

### 3.3 **零新增依赖**改造（重要，直接影响能否被接受）

官方已有 `sha2` 与 `chrono`，我们只要把两处替换掉，**PR 就不需要新增任何 crate**：

| 现在用的 | 用途 | 改成 | 理由 |
|---|---|---|---|
| `md5` | 稳定随机种子（details/sketch/maplib/schedule） | `sha2`（官方已有）取前 16 字节 | 种子只要"稳定且散得开"，用哪个哈希无所谓 |
| `libc` | `localtime_r` 取设备本地时间 | `chrono::Local::now()`（官方已有 chrono） | 少一个平台相关依赖，跨端更稳 |

## 五、本地怎么配合（两条线的定位）

| | 用途 | 基线 | 说明 |
|---|---|---|---|
| 线 A `feat/world-map`（`~/lingchat-main`） | 我们自己的 L-SYuki 产品线 | 我们 SYuki main | 可以自由加 SYuki 定制、web-mock、pnpm 版本适配 |

本地线 B 的职责是**证明改动范围纯净**（门禁）+ 作为素材源头。

## 九、PR 排除清单（**本地/预览环境专用，提 PR 时整段剔除**）

> 依据：机主的硬要求 —— 「抑制浏览器手势的那部分**不能进 PR**」。
> 本节只讲**怎么剔、剔哪些行**；功能本体（地图手势）反过来，**必须留在 PR 里**。

### 9.1 为什么要分成两半

| 半边 | 内容 | 归属 |
|---|---|---|
| **A · 地图手势本体** | 指针事件（平移/捏合）、滚轮缩放、双击复位、阈值与钳制、变换容器 | ✅ **功能**，PR 里应该有 |
| **B · 浏览器手势抑制** | `touch-action: none`、`overscroll-behavior`、长按选择/弹出菜单屏蔽 | ❌ **本地/预览专用**，提 PR 时整份剔除 |

为什么 B 必须剔：它不是"世界模拟"的功能，而是"在手机 WebView 里用起来不别扭"的**环境适配**。
不加它，在舞台上滑动会被浏览器当成滚页面/下拉刷新，地图拖不动（机主实测反馈）；
但它同时会改掉用户在该区域内的默认滚动行为 —— 这是上游不该替用户做的决定。
**A 则相反**：没有 A，地图就是一张死图，属于功能缺失。

### 9.2 隔离方式：单独一个文件 + 一个开关类（三选一里选 2 + 3 的组合）

| 手段 | 做法 | 为什么这么选 |
|---|---|---|
| ① 单独文件 | `src/assets/styles/worldsim-gesture-lock.css`（**55 行，整份都是 B**） | 提 PR 的**文件白名单天然不含它**（9.4 的门禁脚本也不会放行它）—— 剔除 = 删一个文件，不会"漏一半" |
| ② 开关类 | 所有规则都挂在 `.ws-root.ws-nogesture` 下，类由 `useWorldSimGestures.ts` 挂载时打上 | 这个文件一旦被删，那个类就是**没有任何规则的死类**，其余代码一行都不用改 |
| ③ 失败可见 | 引用它的 import 在 `WorldSim.vue` 里**只有一处** | 万一只删了文件、忘了删 import：Vite / `vue-tsc` **当场报错**（找不到模块），而不是悄悄把抑制样式带进 PR |

不选「把 B 写进 `worldsim.css` 的一个小节」的原因：那样剔除只能靠人对着几百行 CSS 找边界，
**忘了也没人发现**（失败是静默的）；而 9.2③ 的失败是响的。硬要求是"不能进 PR"，
那就选"忘了会立刻报错"的方案，而不是"忘了会安静地违规"的方案。
