# 05 · ⭐ 手机端专项设计

> 本方案与常规 Web 地图方案的核心差异：**全流程为手机端设计**。
> 以下每一条都来自 Android / Termux / WebView 真机实测，不是推测。

## 1. 渲染：PNG 优先，规避 WebView 限制

**问题**：Android WebView 有几条硬限制

- 通过 `file://` 打开本地 HTML 时，**WebView 默认禁用 JavaScript**（安全沙箱），页面里的 `<script>` 不执行；
- 内联 SVG / 大体量内联 JS 在部分 WebView 渲染不稳定或直接不显示；
- 因此"前端用 Canvas 画大几何"的常规做法在手机上不可靠。

**方案**：

- 底图与所有地图**一律由服务端渲染成 PNG**，前端只做 `<img>` + DOM 叠加；
- 地图相关 JS 保持轻量（不做大几何运算，只做平移缩放与标记）；
- 页面通过 `http://` 提供（而非 `file://`），并在说明中提示开启 JS 开关。

**效果**：即使浏览器能力受限，地图仍能正常显示与交互。

## 2. 定位：服务端取点，不依赖浏览器权限

**问题**：浏览器 `navigator.geolocation` 在部分 WebView 中不可用，
或需要宿主 App 处理权限回调链，用户侧不易搞定。

**方案**：改用**服务端** `termux-location`（Termux:API）取经纬度。

| 项 | 实测 |
|---|---|
| network provider | **13ms** 返回 |
| GPS provider | 室内会超时（故 network 优先、GPS 兜底）|
| 反查区县 | 准确（实测 → 重庆市 · 涪陵区）|

**要点**：

- `termux-location` 依赖 `termux-api` 的 **KeepAliveService 常驻**，
  服务没跑时 subprocess 会**挂住**（表现为一直不返回，而非报错）；
  处理：失败后自动 `termux-api-start` 再重试一次；
- 结果缓存 60s，避免频繁调用；
- 保留**手动选点**兜底（用户手点地图指定位置）；
- 前端完全不碰权限 —— 这是"服务端取点"最大的好处。

## 3. 触摸交互

- 单指拖动平移、双指捏合缩放、点击区划下钻；
- 缩放范围限制（如 0.15× ~ 20×），避免缩到看不见或放大到糊；
- 层级切换用**缓动飞行**（约 1.2-1.4s，ease-out cubic）而非瞬移——手机屏幕小，瞬移会让人"失去方位感"；
- 工具栏与面板贴合**安全区**（刘海/手势条）；
- 触控目标按手指尺寸放大，避免误触。

## 4. 性能与内存

| 手段 | 收益 |
|---|---|
| 地图用**小 PNG**（8-25KB）而非矢量/瓦片包（MB 级）| 加载快、内存小 |
| 服务端生成 + **按区域 id 缓存** | 二次进入 60-170ms |
| 启动**后台预生成**（参考实现已预生成 106 张）| 首次点开也快 |
| **拼接分级**：本市无缝大图 / 跨城独立区块 | 避免单张巨图 |
| 避免在手机上解析超大 JS 包 | 见下 |

**一个实测教训**：某次升级后所有前端插件被合成**单个 12.6MB JS 包**，
手机上解析/执行明显卡顿（后端响应仍 12-21ms，说明瓶颈在前端解析）。
→ **地图逻辑应作为独立按需加载的模块**，而不是并入主对话页首屏。

## 5. 与对话共存：半透明叠加

地图可作为：

- **半透明背景层**：铺在对话后面，可调透明度 / 一键隐藏；
- **角落小窗**：不挡正文，点开放大。

两种可切换。这样"边聊边看地图"成为可能，而不是必须切走页面。

## 6. 悬浮手机（交互外壳）

地图上有一个悬浮「手机」，点开为手机界面：

| 功能 | 说明 |
|---|---|
| 地图 / 导航 | 看当前位置、搜地点、规划路线 |
| 打车 | 叫车 → 车开到定位处接人 |
| 公交 / 地铁查询 | 线路、到站 |
| 通讯 | 消息 / 电话（接 LingChat 角色）|
| 日程 / 待办 | 接 LingChat 日程 |
| 天气 | 真实天气（wttr.in）|
| 音乐 | 接 LingChat 网易云 |

相当于把"生活中的操作"收进一个入口，也为后续扩展留位置。

## 7. 拼接大图与远处区块

- **本市**：下辖区县拼成一张**连续无缝大图**，可自由漫游不跳图；
- **跨城/跨省**：**独立区块**，用飞机 / 火车 / 轮渡连接。

好处：既保留"远方"的距离感，又不会让单张图无限膨胀（手机内存敏感）。

## 8. 地图库

生成过的区域 / 街区按区域 id 入库，提供查看 / 跳转 / 删除。
配合"按需生成 + 缓存 + 后台预生成"，用户几乎不会等待。

## 手机端踩坑清单（供参考）

| # | 坑 | 表现 | 解法 |
|---|---|---|---|
| 1 | WebView `file://` 禁 JS | 页面 JS 不执行 | 用 `http://` 提供；PNG 优先 |
| 2 | 浏览器定位不可用 | geolocation 超时/拒绝 | 服务端 `termux-location` 取点 |
| 3 | termux-api 服务未常驻 | subprocess **挂住**（非报错）| 自动 `termux-api-start` + 重试 |
| 4 | Overpass 公共服务器慢 | 单次约 19s，偶发超时 | 只读缓存不阻塞 + 后台预热 |
| 5 | 大 JS 包解析卡顿 | 12.6MB 单包明显卡 | 地图逻辑独立按需加载 |
| 6 | 坐标边距单位错 | 地图缩成一个点 | pad 是像素，作用于画布尺寸 |
| 7 | Web Mercator 反投影公式 | 纬度算出 -42° | 用 `π(1-2y)`，注意运算符优先级 |
| 8 | 区县无 `_full` 数据 | 请求卡 19 秒直到超时 | 优先读本级 `.json` |
