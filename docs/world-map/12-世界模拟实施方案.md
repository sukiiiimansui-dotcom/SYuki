# 12 · 「世界模拟」实施方案（MVP）

> 依据：机主 2026-09-12 的需求描述 + 四个关键决策（立绘用现成素材 / AI 在回复末尾输出位置指令 / 「世界」改名「世界模拟」/ MVP 六项全做）。
> 本文是**开工方案**，不是完成记录。

---

## 已确认的四个决策

| 议题 | 结论 | 依据 |
|---|---|---|
| 立绘素材 | **用现成的** —— 角色素材里就有 | 实测：`头像.webp` 388×388（地图标记用）、`正常.webp` 等 **3511×5242**（立绘），还有 `泳装/` 服装变体 |
| AI 位置移动 | **LLM 在正常对话末尾直接输出位置指令**，前端展示时剥掉 | 复用 LingChat 既有的 `【标签】内容` 分段管线（`processor.rs::parse_and_classify_emotional_segments`），标记不进 `following_text` |
| 入口 | 「世界」**改名**「世界模拟」并升级为完整玩法 | 不并存、不重复 |
| MVP 范围 | 入口+定位下钻 / 头像 / 信息面板+立绘 / 存档地图 / 注入上下文 / 小清新UI+加载动画 | 六项全做 |

## 一、入口与首屏流程

```
主菜单 →「开始游戏」→ 那一排（继续游戏 / 开始游戏 / …）
                        └─ 新增「世界模拟」  ← 第四个

点「世界模拟」→ 首次引导（可跳过，之后记住位置）：
  ① 加载动画「正在展开世界…」
  ② 全国地图（省级轮廓）淡入
  ③ 请求定位权限 → 定位中动画
  ④ 命中省份 → 高亮 + 飞入省级地图
  ⑤ 定位到市 → 自动下钻到市
  ⑥ 弹确认：「你现在在 [广州市·越秀区] 吗？」
       ├ 是 → 下钻到该区
       └ 否 → 三级联动选择 / 地图点选
  ⑦ 绘制小区地图：**先给本地草图（毫秒级）**，AI 精绘版本后台生成后淡入替换
  ⑧ 完成 → 角色头像出现在地图上
```

**为什么先草图后 AI**：AI 逐栋绘制要 20 秒左右，首屏干等体验很差；草图（`sketch::make_sketch`）是毫秒级的，玩家立刻能玩，AI 版本好了再替换（这套能力已经有了）。

**全国地图的性能**：全国 geojson 有几千个区划，手机上直接渲染会卡。方案：**首屏只画省级轮廓**（31 个），点进去才加载该省细节。

| 移动 | 见第四节（AI 指令） | 带路径动画 |

地图上的表现：圆形头像 + 描边（角色）/ 玩家自己用不同颜色描边区分；头像下方小字显示名字；点击出信息面板。

## 三、信息面板 + 立绘（侧边栏）

```
点击头像 → 右侧滑出面板（手机上：半透明遮罩 + 立绘）
  ┌──────────────────────────┐
  │        立绘（全身）        │  ← 复用 GameRoleAvatar.vue / GameRolesStage.vue
  │                          │     的图片加载与缩放，不自己造轮子
  ├──────────────────────────┤
  │ 名字 · 当前情绪            │
  │ 此刻在做什么（日程）        │
  │ 当前位置（哪个设施）        │
  │ 与玩家的关系值              │
  │ 长期记忆摘要（可展开）       │
  │ 快捷动作：打招呼 / 约他出门  │
  └──────────────────────────┘
```

⚠️ **性能点**：3511×5242 的立绘解码后约 **73MB 内存**。聊天里已经在用同一批图，
所以只要**同时只显示一张**就与现状持平。若要做"两个角色同时显示立绘"，需要预先生成缩略版立绘（比如 800px 高）。

## 四、AI 驱动位置移动（机主方案）

**流程**：
```
LLM 正常回复（末尾附位置指令）
   ↓ processor.rs 解析
   ├─ following_text → 展示给用户的文字（**已剥掉指令**）
   └─ 新增 map_directive → 传给前端
        ↓
   前端收到回复 → 地图上角色沿路径走过去（动画）→ 到达后触发该地点的可用事件
```

**标记格式建议**（要选一个绝不会出现在正常文本里的）：
```
⟦wm:move=便利店⟧            ← 简单：移动到某类设施的最近一个
⟦wm:move=越秀区·东山口⟧      ← 指定区域
⟦wm:action=喝咖啡⟧          ← 不做移动，只标记行为（供事件系统用）
```
选 `⟦⟧`（数学括号）或 `<<>>` 而不是 `【】`——因为 `【】` 已经被情绪/动作标签占用了。

**Prompt 侧**：在系统提示里加一段说明 —— "如果剧情需要角色移动，在回复最后一行附上 `⟦wm:...⟧`；
不要向用户解释这个标记，也不要让它出现在正文里。"

**兜底**：LLM 不输出或格式错 → 位置不变（保持日程规则算出来的位置），不报错。

**成本**：几乎为零 —— 不额外调用 LLM，只是在已有的回复末尾加几个 token。

## 五、存档地图（接入 LingChat 存档）

机主原话："将地图库接入 LingChat 原有的存档系统（单开一个行列：存档地图）"。

```
存档列表（原有）              存档地图（新增列）
┌────────┬──────────┬──────────────┐
│ 存档名  │ 时间/角色 │  🗺 地图       │
├────────┼──────────┼──────────────┤
│ 存档A   │ …        │ [小区缩略图]  │  ← 点击进地图 / 显示当前位置
│ 存档B   │ …        │ [缩略图]      │
└────────┴──────────┴──────────────┘
```

**存什么**（建议）：当前位置（省市区县小区）+ 布局哈希 + 角色地图位置 + 关系值 + 事件日志摘要。
**不存**：完整布局（体积大）—— 靠哈希命中地图库复用；未命中就重新生成。

**待确认**：多存档是否共享地图库；地图数据体积预算（见待确认 Q3）。

## 六、地图注入对话上下文

按机主"将地图注入对话上下文提供给对话模型"：

**注入内容**（系统提示的固定段落，随位置变化刷新）：
```
【当前场景】
你（角色名）现在在：广州市·越秀区·东山口·便利店里
用户现在在：广州市·越秀区（附近 300m）
时间：19:24（傍晚）  天气：小雨 22°C
附近：咖啡馆(80m)、地铁站(200m)、公园(350m)
最近发生：刚才在便利店买了伞
```
**注入频率**：位置/天气/时间变化时更新，其余轮次复用（省 token）。
**成本**：约 +80~150 token/轮，可接受。

## 七、小清新 UI + 加载动画

**配色（建议，可换）**：薄荷绿 `#8fd6c0` / 奶油白 `#fdfbf6` / 雾蓝 `#a8c8e8` / 暖灰文字 `#5a6b73`，
圆角 14–18px，毛玻璃卡片，阴影轻。地图主题仍保留现有三套（高德/暗色/水系），世界模拟 UI 用独立小清新皮肤。

**加载动画**（CSS 实现，不引第三方库）：
| 时机 | 动画 |
|---|---|
| 初始化 | 地球/地图轮廓逐笔勾勒（SVG stroke-dashoffset） |
| 定位中 | 脉冲波纹从中心扩散 |
| 地图加载 | 骨架屏 + 淡入 |
| AI 绘制中 | 已实现的逐栋生长动画（DistrictLive 那套） |
| 区域切换 | 缩放 + 淡入淡出 |
