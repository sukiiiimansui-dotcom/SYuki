# 04 · AI 生成街区（LLM 布局 + 代码绘制）

## 核心思路

**地理位置真实，街区布局虚构**——兼顾真实感与可探索性。

```
用户定位 → 反查真实区县（如「重庆市·涪陵区」）
   ↓
LLM 依据「真实区县名 + 剧情上下文」生成街区布局 JSON
   ↓
代码把布局绘制成街区图（可复现、可重画）
   ↓
用户决定：保留 / 重画 / 不要
```

## LLM 输出的结构

```json
{
  "name": "越秀·钦灵居",
  "size": 20,
  "buildings": [
    {"x":2,"y":2,"w":3,"h":3,"type":"residential","name":"1号楼"},
    {"x":8,"y":8,"w":4,"h":2,"type":"school","name":"越秀小学"}
  ],
  "roads": [{"x1":0,"y1":0,"x2":20,"y2":0,"type":"main"}],
  "parks": [{"x":5,"y":5,"w":4,"h":3}],
  "water": [{"x":10,"y":10,"w":3,"h":2}]
}
```

- `size`：网格边长（基础 20，探索扩大时递增）
- `building.type`：residential / commercial / school / hospital / office / shop
- `road.type`：main / secondary / path
- 约束：建筑不重叠；数量随 `size` 增长（约 `size/2` 栋）

## 真实区县名的作用

区县名既进入 LLM 提示（让命名与布局贴合当地），也用于生成后的小区命名
（实测得到「越秀雅苑」「越秀钦灵苑」等）。

## 绘制

按类型用不同色块 + 描边 + 窗格纹理；公园 / 水体单独色块；
标注建筑名与小区名（格子够大时才画，避免糊成一片）。

## 探索扩大

`expand` 参数控制向外扩展：`size = 20 + expand * 8`

实测效果：

| expand | 网格 | 建筑 | 道路 |
|---|---|---|---|
| 0 | 20 | 11 | 4 |
| 1 | 28 | 19 | 10 |
| 2 | 36 | 20 | 23 |

即"随着探索，街区越来越大、越来越丰富"。

## 工程实践：LLM 返回的健壮解析

实际调用中遇到过这些问题，值得记录：

1. **`content` 为空、内容全在 `reasoning_content`**
   部分模型（实测 `deepseek-flash` 一类）即使传 `enable_thinking: false` 也会把内容放进 reasoning 字段。
   处理：`content` 为空时回退读 `reasoning_content`。

2. **`finish_reason: length` 导致截断**
   reasoning 吃掉大量 token，`content` 还没输出就被截断（表现为"生成失败"）。
   处理：**加大 `max_tokens`**，给 reasoning 留足空间。

3. **JSON 提取要抗干扰**
   reasoning 文本里常夹杂多个 `{}` 片段，用 `find('{')`~`rfind('}')` 会取错。
   处理：用 `JSONDecoder().raw_decode()` **从每个 `{` 位置逐个尝试**，取第一个能完整解析的 dict。

## 保留 / 重画

生成结果**不自动提交**：每次生成后由用户选择保留、重画（换风格重新生成）或丢弃。
重画会换一种风格重新生成，避免"同样的东西重来一遍"的无意义感。
