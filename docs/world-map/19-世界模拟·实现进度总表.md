## 五、本轮补掉的三个**静默缺口**（都是"不报错但功能不生効"）

1. **没人往 `MapRuntime` 推状态** —— 全仓只有 `useWorldTrips.ts` 在推。
   后果：`world_sim_enabled()` 恒 `false` → 指令剥离器不启用、注入摘要恒为空串。
   → 新增 `wsRuntimePush.ts` + `WorldSim.vue` 三处接线。
2. **设施表从没被生成过** —— `facilities::generate_all()` 在 Tauri 侧零调用者。
   后果：注入的「附近：咖啡馆(70m)…」永远缺失；`move_to`/派发解析不出目的地只打 warn。
   → `bridge.rs` 在布局落地时生成并 `install_facilities()`。
3. **`indoor` 字段根本不存在** —— 停电/停水/失眠/睡过头这批**仅室内**事件永不触发。
   → `facilities.rs::indoor_of()` 给每条设施记录写 `indoor`；`event_cmd.rs` 按名字反查
   补齐 `place_kind`（否则"在餐厅提高消费类"等权重修正也不生效）。

三个的共同特征：**不影响编译、不报错、只是"从来没发生过"**。所以本文档单列一节。

## 七、两个必须记住的结论（踩过才知道）

### 1. 工具权限：官方没有「自动放行」这回事
`tool_permissions.rs` 的实际逻辑是 **场景组 × 角色组** 二维矩阵：
- `scene_admin.all_tools = true` 只让**场景**侧不拦
- 最终由**角色组**决定：默认角色组 `enabled = false` → `allowed_tools()` **直接返回空集**
- 也就是说：**用户不在设置页里开工具，模型一个工具都拿不到**（这是官方既有行为，不是我们引入的）
- 我们的三个地图工具因此**默认不可达**。好消息：**位置信息已经通过 `summary.rs` 的注入常驻在系统提示里**，角色照样知道自己在哪；`move_to` 则主要走 `⟦wm:…⟧` 文本指令通道（不依赖工具权限）
- 若要开：在 `ai_service/tools/settings.rs` 的 `TOOL_GROUPS` 里把三个名字加进 `("scene", …)` 组（1 行，零前端改动，设置页「场景」开关即生效）

### 2. 注入点是「锁内同步」，一辈子不能 await
`api/chat.rs` 持 `game_status` 锁 → `add_line` → `refresh_memories` → `sync_memories` → 我们的 `injection_for()`。
所以：**注入函数必须同步、零 await、只读内存快照**（天气只读已抓好的快照，>1800s 当没有）。
前端契约：**退出世界模拟时必须推 `{scene: null}`**，否则会一直带着上次的地图上下文；`actors` 的键必须等于角色的 `display_name`（= `settings.yml` 的 `ai_name`）。
