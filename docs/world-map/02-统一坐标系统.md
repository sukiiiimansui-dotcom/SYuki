# 02 · 统一坐标系统

所有层、设施、交通、角色共用一个坐标模块，**前端 JS 与服务端 Python 双实现，算法完全一致**（交叉验证过世界坐标一致到小数点后 10 位）。

## 四层坐标互通

```
地理坐标 (lng, lat)
    ↕
世界坐标 (Web Mercator 归一化 0..1)      ← 与缩放无关，可跨层比较
    ↕
画布坐标 (像素)                          ← 给定 bbox + 画布尺寸 + 边距
    ↕
网格坐标 (小区内部 gx, gy)                ← 给定锚点 + 每格米数
```

## 核心公式

**地理 → 世界**（Web Mercator 归一化）：
```js
x = (lng + 180) / 360
y = 0.5 - Math.log((1 + sin(lat)) / (1 - sin(lat))) / (4 * Math.PI)
```

**世界 → 地理**：
```js
lng = x * 360 - 180
lat = Math.atan(Math.sinh(Math.PI * (1 - 2 * y))) * 180 / Math.PI
```
> ⚠️ 注意是 `1 - 2*y`，写成 `0.5 - y*2` 会因运算符优先级得到错误结果（我们踩过这个坑，往返验证立刻能发现）。

**世界 → 画布**（把 bbox 适配到画布）：
```js
scale = min((w - 2*pad) / (maxx - minx), (h - 2*pad) / (maxy - miny))
cx = (x - minx) * scale + pad + 居中偏移
cy = (y - miny) * scale + pad + 居中偏移
```
> ⚠️ 边距 `pad` 是**像素**，必须作用在画布尺寸上，**不能**直接加在世界坐标跨度上（世界坐标跨度是 0~1 量级，加 60 会让 scale 变成个位数，地图缩成一个点——我们踩过）。

## 小区为什么必须单独一层

一个典型小区：20×20 格、每格 20 米 = 400m × 400m。

换算到世界坐标跨度约 **1.1e-5**——已接近双精度浮点在该量级的有效精度边缘。

因此：
- 小区**不参与世界坐标运算**，用「网格层」局部坐标渲染；
- 网格 → 世界只在需要「小区在地图上的锚点」时转换一次；
- 这样既保证小区内部精度，又能把小区定位到真实经纬度上。

**这是分层坐标存在的根本原因**，不是过度设计。

## 米与度的换算

```js
METERS_PER_DEG_LAT = 110574                  // 纬度方向基本恒定
metersPerDegLng(lat) = 111320 * cos(lat)      // 经度方向随纬度收缩
```
> 校验：广州纬度（23.1°）每度经度约 **102,372 m**（赤道 111,320 m），符合预期。

## 双实现一致性验证

| 检查项 | 结果 |
|---|---|
| 经纬度 ↔ 世界 往返（北京/广州/涪陵）| 零误差 |
| 经纬度 ↔ 画布 往返 | 精确还原（113.2640, 23.1290）|
| 网格 ↔ 世界 往返（每格 20m）| 精确还原（10.00, 10.00）|
| JS / Python 世界坐标 | 完全一致（0.8146222222, 0.4339332408）|
