# 二维世界地图系统 · 设计方案与实施记录

> 为 [LingChat](https://github.com/SlimeBoyOwO/LingChat) 设计的二维世界地图系统。
> 上游讨论见 issue **[#804](https://github.com/SlimeBoyOwO/LingChat/issues/804)**。
> **全流程为手机端设计**（Android / WebView），不是桌面方案的简化版。

## 一句话概括

让角色不再只存在于对话流里，而是生活在一张**可下钻、可游走的地图**上 ——
从真实世界的省市区县，一路下钻到 AI 生成的街区。

```
世界地图（真实投影）
  └─ 省 → 市 → 区县          （真实行政区划边界，点击下钻）
        └─ 小区 / 街区        （AI 生成布局，代码绘制，可游走）
```

## 关键设计决策（与最初设想不同的地方）

| 议题 | 最初设想 | 现在的做法 | 原因 |
|---|---|---|---|
| 渲染格式 | PNG（PIL 服务端渲染） | **SVG** | 单张 8–25KB（小一个数量级）、缩放不糊、中文交给系统字体（省掉字体打包）、可做图层开关与生长动画 |
| 服务端 | Python 侧车服务 | **Rust / Tauri 命令** | 手机上没有侧车进程；命令直连，图片用 data URL |
| 定位 | `termux-location` | **手动坐标 / IP 兜底**（GPS 规划中） | `termux-location` 只有 Termux 内部能用，打包成 APK 必然失败 |
| 地图尺寸 | 固定 1000×760 | **画布跟容器尺寸走** | 否则手机上 8.2px 的中文被缩到 ≈3px、完全看不清（现在 1:1，实际放大 ≈2.7 倍） |
| 工具接入 | 在回复末尾输出位置标记 | **优先官方 `Tool` trait**（`map_*` 工具） | 官方 `docs/function_call/extension.md` 的三步扩展法，自带权限与错误回填；标记法降级为"模型不支持 tool calling 时的兜底" |

> ⚠️ 注意：官方工具执行有 **2 秒超时**，所以"AI 绘制小区（约 20 秒）"**不能**做成工具，只能是后台任务。

## 为什么值得做

LingChat 已有相当丰富的**状态**：`useHeartbeat` 心跳、`proactive_system` 的
`UserState`（IDLE/BROWSING/WORK/GAME/CASUAL）与 `ProactiveEvent`（想念/日程/待办）、
角色列表、日程、记忆系统。

这些状态**本质都是「角色此刻在做什么」**，但目前只能以文字与面板呈现。
地图把它们**可视化为位置与移动** —— 不新增状态，只多一个空间维度。

## 技术栈（当前实现）

- **Rust**：`src-tauri/src/world_map/`（14 模块：坐标/几何/草图/AI 流式生成/渲染/统计/行政区划/地图库/OSM/日程/交通/设施）
- **前端**：Vue3 + Tauri 命令（SVG 以 data URL 进 `<img>`，容器尺寸随 `ResizeObserver` 传给后端）
- **数据**：阿里 DataV GeoAtlas（行政区划 GeoJSON，本地缓存）、wttr.in（天气）、OpenStreetMap/Overpass（可选真实地物参考）
- **AI**：任意 OpenAI 兼容 LLM（生成街区布局 JSON，SSE 流式逐栋出图）
- **验证**：130 个 Rust 单测 + `vue-tsc` + 四平台 `cargo check` 矩阵
