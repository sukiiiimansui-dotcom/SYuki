# 二维世界地图系统 · 设计方案

> 为 [LingChat](https://github.com/SlimeBoyOwO/LingChat) 设计的二维世界地图方案。
> **全流程为手机端设计**（Android / Termux / WebView），并非桌面端的简化版。
>
> 这是我们在改造 LingChat（L-SYuki 项目）过程中形成并**已在真机验证**的实现思路，
> 整理成文档供 LingChat 官方参考。

## 一句话概括

让角色不再只存在于对话流里，而是生活在一张**可下钻、可游走的地图**上——
从真实世界的省市区县，一路下钻到 AI 生成的街区。

```
世界地图（真实投影）
  └─ 省 → 市 → 区县          （真实行政区划边界，点击下钻）
        └─ 小区 / 街区        （AI 生成的微观地图，可游走）
              └─ 随剧情探索向外扩展
```

角色（钦灵等）在地图上有真实坐标，会随 LingChat 的状态**移动、停留、留下足迹**；
玩家也能通过地图上的「手机」打车、查天气、听歌、发消息 —— 把对话之外的生活感补上。

## 为什么值得做

LingChat 目前已有相当丰富的**状态**：

- `useHeartbeat` 心跳（用户活跃度）
- `proactive_system` 的 `UserState`（IDLE / BROWSING / WORK / GAME / CASUAL）
- `ProactiveEvent`（想念 / 日程 / 待办）
- 角色列表、日程系统、记忆系统

这些状态**本质上是「角色此刻在做什么」**，但当前只能以文字与面板呈现。
地图能把这些状态**可视化为位置与移动**——同样一套状态，多了一个空间维度的表达。

## 已在真机验证的能力

| 能力 | 实测结果 |
|---|---|
| 全国省/市/区县数据 | DataV GeoAtlas，34 省级 + 各市下辖区县，已全部预缓存 |
| 地图渲染 | 4 种风格，单张 8-25KB；缓存后 **60-170ms** 秒开 |
| 城市拼接大图 | 广州/深圳/重庆实测 900ms-2.7s（首次生成），无缝 |
| 定位 | `termux-location` network provider **13ms**，反查区县准确 |
| AI 生成街区 | LLM 返回结构化布局 + 代码绘制，单次含 10-19 栋建筑 / 4-23 条道路 |
| 真实天气 | wttr.in，30 分钟缓存 |
| 预生成规模 | 106 张地图已预生成 |

## 技术栈（参考实现）

- **服务端**：Python + PIL（确定性地图渲染）、标准库 HTTP 服务
- **前端**：原生 JS + `<img>` / Canvas 叠加（不依赖重框架）
- **数据**：阿里 DataV GeoAtlas（行政区划 GeoJSON）、wttr.in（天气）、OpenStreetMap/Overpass（可选真实地物参考）
- **AI**：任意 OpenAI 兼容 LLM（生成街区布局 JSON）
- **定位**：Termux:API `termux-location`（服务端取点）
