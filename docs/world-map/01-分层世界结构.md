# 01 · 分层世界结构

## 5 层结构

| 层 | 名称 | 内容 | 数据来源 | 交互 |
|---|---|---|---|---|
| 0 | 世界 | 全球国家 / 大区 | 真实世界投影图（1600×800 PNG）| 点击任意处进入本国 |
| 1 | 省 | 全国省级行政区（34 个，含港澳台）| `100000_full.json` | 点击省 → 下钻 |
| 2 | 市 | 省下辖市 | `{省adcode}_full.json` | 点击市 → 下钻 |
| 3 | 区县 | 市下辖区县 | `{市adcode}_full.json` | 点击区县 → 拼接大图 |
| 4 | 小区 | AI 生成的街区 | LLM 布局 + 代码绘制 | 游走 / 探索扩大 |

## 数据源

**阿里 DataV GeoAtlas**（`https://geo.datav.aliyun.com/areas_v3/bound/`）

- `100000_full.json` → 34 个省级（含 `adcode` / `name` / `center` / `centroid` / `level` / `childrenNum`）
- `{adcode}_full.json` → 该区划的**下辖**边界（含下辖 feature 的 adcode）
- `{adcode}.json` → 该区划**本级**边界（区县无 `_full` 版本，需回退本级）

**重要实践**：区县层级**没有** `{adcode}_full.json`。若一律按 `_full` 请求，会陷入下载重试直到超时（曾导致区县地图卡 19 秒）。
正确做法是**优先读已缓存的本级 `.json`**，无缓存再依次尝试 `_full` → 本级。

## 下钻机制

```
点击地图 (canvas x,y)
   → 用统一坐标系统反算经纬度
   → 调 /api/locate 反查所在区划 adcode
   → 载入该 adcode 的下级边界并重绘
```

**点击命中**不用前端几何求交（大几何在手机上求交很慢），而是：
canvas 坐标 → 经纬度 → 服务端反查。服务端有完整的边界数据与点包含算法（ray-casting，需正确处理 MultiPolygon 与内环/洞）。

## 面包屑与层级状态

维护一条 `path`：`[全国, 省, 市, 区县]`，任意一级可点击回跳；
搭配「上一级」按钮与「直达小区」按钮，避免手机上层层退回的疲劳。

## 拼接大图与远处区块

- **本市**：把该市下辖区县拼成**一张连续无缝大图**（相邻区县共享同一 GeoJSON 边界，天然无缝），可自由漫游不跳图；
- **跨城/跨省**：作为**独立区块**，通过飞机 / 火车 / 轮渡连接——既保留「远方的感觉」，也避免单张图无限膨胀拖垮手机内存。

## 地图库

生成过的区域 / 街区图按 `{adcode}_{style}` 入库缓存：

- 二次进入 **60-170ms** 秒开；
- 提供地图库页面查看 / 跳转 / 删除；
- 启动时后台**预生成**常用区域（参考实现已预生成 106 张：34 省 × 3 风格）。
